# DevSharp internal contract (for contributors)

DevSharp is a Claude Code plugin + standalone CLI that shows short technology
learning cards. **It never calls an LLM.** Node.js >= 18, **zero runtime
dependencies**, CommonJS (`'use strict'; require/module.exports`), tests use the
built-in `node:test` + `node:assert/strict`, run with `npm test` (`node --test test/`).

## Layout

```
.claude-plugin/plugin.json, marketplace.json
hooks/hooks.json                 Claude Code hook registration
commands/*.md                    /devsharp:* slash commands (intercepted by hook, zero tokens)
cli/devsharp.js                  standalone CLI
src/core/paths.js                paths(env) -> {home, config, state, packs, cache, projects, updates, sources, refreshLock}
src/core/fsutil.js               readJson(file, fallback), writeJson(file, data) atomic, isInside(parent, child)
src/core/sanitize.js             cleanText(s, {maxLen, multiline}), cleanUrl(s, {allowHosts})
src/core/config.js               load/validate config
src/core/store.js                state.json (history, per-item progress, sessions)
src/core/knowledge.js            loads + validates packs
src/core/techmap.js              dependency/file signal -> topic ids
src/core/detect.js               project technology detection
src/core/select.js               scoring / anti-repetition / mode choice
src/core/render.js               card rendering
src/core/stats.js                learning statistics
src/updates/*.js                 technology-update feeds (fetch, parse, cache)
src/claude/hook.js               hook entry: node hook.js <event>
knowledge/<category>/<topic>.json   bundled packs
knowledge/index.json             generated by scripts/build-index.js
updates/sources.json             default update sources
```

## Knowledge pack format (`knowledge/<category>/<topic>.json`)

```json
{
  "schema": 1,
  "topic": "postgresql",
  "category": "databases",
  "name": "PostgreSQL",
  "items": [
    {
      "id": "postgresql-mvcc-001",
      "type": "concept",
      "difficulty": "medium",
      "title": "MVCC",
      "body": "PostgreSQL uses multi-version concurrency control ...",
      "question": "Why can this reduce read/write blocking?",
      "answer": "Readers see a snapshot of row versions ...",
      "tags": ["concurrency", "transactions"],
      "source": { "name": "PostgreSQL Documentation — Concurrency Control", "url": "https://www.postgresql.org/docs/current/mvcc-intro.html" }
    }
  ]
}
```

Item rules:
- `id`: `^[a-z0-9][a-z0-9._-]{2,80}$`, globally unique, prefixed with the topic.
- `type`: `fact` | `think` | `concept` | `why`.
  - `fact`: `title`, `body` (1–3 sentences). `question`/`answer` optional.
  - `think`: `title`, `question` (a scenario to reason about), `answer` (2–4 sentences). No `body` needed.
  - `concept`: `title`, `body` (2–4 sentence explanation); optional `question`+`answer` "Think:" prompt.
  - `why`: `title`, `question` ("Why does X ...?"), `answer`.
- `difficulty`: `easy` | `medium` | `hard`.
- `topic` on an item is optional (defaults to pack topic). `tags`: lowercase strings.
- Text: plain text, no markdown, no ANSI, `body` <= 400 chars, `answer` <= 600 chars, `question` <= 300 chars, `title` <= 60 chars.
- `source` required: official docs/spec/RFC/primary source, https URL.

## State/cache files (under paths().home)

- `cache/updates.json`: `{ "version": 1, "fetchedAt": <ms>, "sources": { "<id>": { "fetchedAt": <ms>, "ok": true, "error": null, "count": 3 } }, "items": [ { "id": "upd-<sha1-12>", "sourceId": "nodejs", "topic": "nodejs", "name": "Node.js", "title": "...", "url": "https://...", "published": <ms|null> } ] }`
- `cache/projects.json`: detection cache keyed by absolute dir.
